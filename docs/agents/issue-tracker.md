# 飞书事项跟踪

项目已有 `docs/agents/issue-tracker.md` 时按项目配置；否则使用本适配。任务清单由用户指定，或从当前任务的 `tasklists` 读取。多个清单且无法判断归属时询问用户。参考清单不作为所有项目的默认目的地。

## 读写任务

- 使用 lark-task skill 和 `lark-cli`。调用原生接口前读取 schema；CLI 缺少能力时查官方 OpenAPI，不猜命令。
- 从任务链接取 `guid`；`t300128` 这类展示编号不能替代 GUID。清单链接中的 GUID 是清单 ID。
- 已知清单时，读取 `tasklists.tasks` 并遍历分页；任务全文用 `tasks.get`，子任务用 `subtasks.list`。处理事项前读描述、关联规格和评论。
- 应用身份用于应用有访问权的资源；个人资源按用户授权使用用户身份。空列表不能证明资源为空，先核对身份和访问权。鉴权、权限和二维码处理遵循 lark-shared。
- 新建前检查当前任务及其子任务，续做已有事项。保留已有描述、负责人和无关字段；缺少负责人、日期时标明待确认。

## 规格与 tickets

规格正文保存为飞书文档，位置和互链见 [artifacts.md](artifacts.md)。上游要求将 spec 发布到 tracker 时，将规格链接及摘要写入对应飞书任务，正文以文档为准。

拆分由上游 to-tickets 的确认步骤决定。已有需求任务作为父任务，每个工程 ticket 为其子任务，保留目标、验收条件、规格链接和阻塞关系。无父任务时在选定清单创建任务。核对新任务是否加入目标清单；子任务关系本身不保证清单成员关系。

优先使用平台原生依赖关系，并先确认当前 CLI/API 的写入能力。无法写原生依赖时，在描述中维护 `Blocked by` 段，逐项记录阻塞任务 GUID 和 URL；无阻塞写 None。执行前重新读取阻塞项，只有全部满足完成条件才进入 ready frontier。原生与文本关系冲突时先核实，不自行取其一。

主会话汇总跨 ticket 进度并更新父任务；实现子任务的 Agent 只更新自己的 ticket。拆分任务不关闭父任务。

## 状态

分流角色映射见 [triage-labels.md](triage-labels.md)。开始实现记「进行中」，代码及检查完成并提交 PR/MR 后记「待验证」。合入或业务验收是否属于完成条件，以任务约定为准；满足全部条件后再记「已解决」并完成任务。拒绝需记录理由，不等同于已解决。

仅改当前清单存在的字段，按字段名、选项名解析 GUID。字段不存在或含义不清时说明缺口，先保留状态，不创建新字段或猜选项。历史 Intenting 状态保留供查询，新流程不要求经过该状态，也不以状态值自动触发 skill。

## 适配依据
