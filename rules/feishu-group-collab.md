# 飞书群协作规则

## 主动找人：协作靠主动 @，别只等被点名

群里分工靠 @ 唤起，主动找人 = 主动 @ 对的人，让该醒来的人醒来。拿活先过判
定：**这活归谁做最划算？** 自己顺手 → 做，不找人；部分或整体归别人 → 主动
@ 委派或转交，别默默扛下、别干等点名。节奏克制：确有分工价值才出手，不刷存
在感。主动 @ 出手和回声机制不冲突——你 @ 出去，对方照常 @ 回你，对话链依然
闭合。

主动出手有两条，各自触发点见下文：

- 自己手上活需要别人 → 按「发协作消息」委派条主动 @ 委派。
- 群里消息明显归别的 agent → 按「收群消息」第 3 条主动 @ 转交。

## @ 回机制：谁 @ 你，回复就 @ 回谁

群里消息靠 @ 唤起对方——不 @ 的消息对方不会被唤起。因此任何回复一律 @ 回
发起者，不省略：

- 人类 @ bot → bot 回复必 @ 回那个人类。
- botA @ botB → botB 回复必 @ 回 botA。
- 被 @ 到你 = 对方点名唤你，必须回应——接 / 拒 / 延 / 转交 / 说明归属都算，
  唯独不许因"这活归别人"静默不出声。判定主体归别的 agent → 回应里 @ 回对方
  说明归谁并转交；同一条消息 @ 了多人 → 也出声认领或转交，别等别人先动。

被 @ 的一方回复时 @ 回，对话链才闭合；@ 发起方收到回复后醒来，结合对方回复
的内容判断下一步，三选一：

1. 还需要对方继续做 → 再 @ 对方，开启下一轮。
2. 自己能处理剩余 / 需转给别人（比如任务被拒，得转告人类原始发起人）→ 不
   @ 对方，独自继续处理。
3. 事情已经了结 → 结束，不再 @ 任何人。

**委派出去的任务，接收方完成时必须 @ 回委派方**——@ 是委派方得知"已完成"
的唯一通道，不 @ 对方不会醒来，任务完成与否无从知道。委派方收到"已完成"
后照上面三选一收尾（验收 / 续排 / 通知原始发起人后结束）。完成这一下 @ 回
和对话中每步回应必 @ 回一致，不可省略。

## 发协作消息：自然语言表明意图

发消息不套机器前缀，直接自然语言说清意图：

- 委派任务给另一个 agent → @ 对方，说清要对方做什么、为什么判定这事归对方。
  必须附上飞书任务 id（如果有，对方据此定位完整需求，不依赖转述）。对方
  完成时会按回声机制 @ 回你报"已完成"——这是必须的（见 @ 回机制节），否则
  你不会知道任务完成。委派时补一句完成后对方要做什么即可：验收后 merge / 告诉我（@回来） / 收到即了结，让对方知道要不要等你进一步指令。对方回应这笔委
  派（接受 / 拒绝 / 延后）的那一下同样必 @ 回。
- 回应另一个 agent 的委派（接受 / 拒绝 / 延后 / 已完成）→ 意图和理由说清，
  回复 @ 回委派方：接受 → 说"接手开工"；拒 / 延 → 带理由；已完成 → 带 MR
  链接。回应里可以带上你的**预期**——你希望对方下一步怎么走，给对方判断提供
  依据：拒 → 可说"请转告原始发起人"或建议改派给谁；延 → 可说"改期再派我"；
  已完成 → 可说"请验收"或"直接转发起人"。

## 收群消息：判意图

收到消息先按内容判断意图：

1. 委派请求 → 对方想请你处理一项任务。接受后开工，**结果落定时一次性 @ 回
   委派方**：做完 → 报"已完成"；拒绝 / 延后 → 当场 @ 回带理由（见"回应另一个
   agent 的委派"条）。不静默交付。

2. 对你发出的委派的回应（对方已按 @ 回机制 @ 回你）→ 更新本地对该任务的
   认知，结合回复内容决定下一步（三选一）：
   - 接受 → 任务已转出，等对方最终"已完成"回报（回声必 @），或就此了结。
   - 拒 / 延 → 若有人类原始发起人，@ 回那个人转告"尚未处理"（不能让需求方
     以为已经在做）；没人则改派其他 agent 或结束。
   - 已完成 → @ 那个人一句结果。

3. 与你无关、但明显归别的 agent / 人类的消息 → 主动 @ 那个人转交，别干看
   着。不 @ 对方不会醒来（见 @ 回机制），干等这活就没人动。@ 时附一句判定
   依据——谁该做、为什么归他，照主动找人总节克制节奏，不刷屏。

## 怎么 @ 人：回复文本里直接嵌 `<at>` 标签

@ 人**必须**在自己的回复文本里直接写 `<at user_id="对方open_id">对方名字</at>`
写法：

```
<at user_id="对方open_id">对方名字</at> 想说的话
```

属性名固定是 `user_id`（值填对方 open_id），没有 `open_id` 这种属性名写法。
